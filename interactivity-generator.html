Sample · Tool for designers

Interactivity Generator

Helping our team create small, useful learning interactions.

I designed and built a tool for Duke’s learning design team to turn course content into interactive activities. It has two connected parts: a generator that helps designers create and edit an activity, and a plugin that places the finished activity in Coursera.

01 · Where we started

Where we started

Sometimes a single concept benefits from a small interaction: a quick question, a sequence to arrange, or a visual learners can explore.

I wanted our team to have an easier way to create those moments in Coursera. I started with the decisions a designer needs to make: what learners should understand or practice, which format could help, and how to review and prepare the activity for a course. Those decisions became the structure of the tool.

02 · How it works

Building the two parts

With the support of Claude Design and Claude Code, I first built a plugin that embeds finished HTML and JavaScript in the Coursera course environment.

Then I built the generator to support the work that comes before that. A designer describes what they want learners to understand or practice, and the tool helps them explore possible interaction formats.

Designers can also choose a format directly when they already have something in mind.

The tool itself uses Claude API to recommend formats and build activities.

03 · Recommendations

Keeping the learning goal in view

The generator uses Claude and a set of learning design guidelines to suggest formats such as a short quiz, a tabbed explorer, or a sequencing activity. The recommendations begin with what learners need to understand or practice.

I included guidance for requests that need more detail, contain too much for one activity, or may work better in another format. The designer can consider the recommendation, explore another option, or choose a format directly.

04 · Review and edit

Giving designers room to review and edit

Once an activity is generated, the designer gets a working preview. They can try it, explore alternatives, and edit the visible text without changing the code. Subject-matter experts can review the content with the designer before it goes into a course.

I built those steps into the workflow because generating an activity is only part of preparing it for learners. Designers also need room to check the content, adjust the language, and consider whether the interaction supports the intended learning.

When ready, they can export the Coursera configuration and a static text version of the content.

06 · Access

Providing another way to use the content

Each activity comes with a static text version that learners can use as a study reference or another way to access the material. It also provides readable content for course features that may not interpret the interactive component directly.

I made the companion text part of the export workflow so designers receive both versions together. This gives them another way to support access to the content as they prepare the activity for a course.

07 · Looking back

What I wanted to make easier

I designed the tool around the work that happens between having an idea for an interaction and placing it in a course. Choosing a format, trying it, editing the content, and preparing the output all happen in one place.

My aim was to make small learning interactions more practical for our team to develop, while keeping the designer involved in the choices that shape the learner’s experience.
