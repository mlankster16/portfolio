01 · Certification path

Three levels tied to a job

Each level matches what admins actually do at that stage, from setting up a first team to designing access for a large organization. Every exam follows a published blueprint, so candidates know what is tested and how much each area counts. Select a level to see its format and blueprint.

02 · Sandbox lab

Practice in a copy of the real console

Labs run in a sandbox that behaves like the product, so admins can make mistakes without affecting real users. Each lab starts from a support ticket. Hints get more specific each time they’re requested, and each request is logged so we can see which steps need better teaching. Set up the contractor’s access, then save.

03 · Exam items

Questions that look like real tickets

Exam items test whether an admin can apply a concept in context. Each distractor matches a mistake admins commonly make, so a wrong answer shows which misunderstanding to address. Try the item.

04 · Keeping content current

When the product changes, the course follows

Every lesson, lab and exam item is tagged to the features it covers. When a release ships, the tags show exactly which content needs an update, and AI drafts the first revision from the release notes for a subject matter expert to review. Select a change to see what it affects.

05 · Measuring effectiveness

Does certification reduce support load?

The goal is admins who can solve problems without filing a ticket, so the measures follow that from the first lab to the first year on the job.
During trainingLab attempts, hints requested and time on task, sent to the LMS as xAPI statements
At certificationPass rates by blueprint domain, and item analysis to retire questions that don’t separate strong and weak candidates
On the jobSupport tickets and configuration errors from certified customers compared with uncertified ones
